How this works

ChatGPT and Claude consumer subscriptions are not API credentials. Use an OpenAI Platform key or a Claude Console key. Gemini uses a Google AI Studio key. OpenRouter supports an official OAuth sign-in. The Claude Code card is an experimental bridge to the official CLI: it uses your Claude Code sign-in, never reads its credential files, and is subject to Anthropic's terms.

Local providers need no key. The app never submits an application; the agent can prepare a resume and check readiness, then you review and click Submit.

Test chat sends a tiny billable request. Refresh models only asks the provider for its model list. Use this model writes the active selection to config.yml without a key.

Use Ollama or LM Studio if you want candidate context to stay on this machine.

Where the context goes

When you use the agent, the active provider receives the candidate context and the messages you type. The default context omits email and phone. Job descriptions are treated as untrusted input. Raw GitHub README text is not sent unless you imported it as an ordinary profile fact.

The Claude Code card does not read or store Claude Code credentials. It invokes the installed claude CLI, which authenticates itself. That provider is text-only and cannot call JobForge tools or submit applications.

Scanning, scoring, the quality gate, and browser filling do not call a provider. Resume tailoring uses the active provider when tailoring.mode is auto or llm; deterministic skips it, and auto falls back to the deterministic selector when no provider is available. Cover letters and AI answer drafts also use the provider when enabled.

The exported Agent Skill and MCP server do not need a JobForge provider for status, search, fit, readiness, profile, or application-summary reads. Their host agent supplies the model. A resume request still renders inside JobForge, so it uses the provider only when tailoring is configured to require one.
