# Offline end-to-end smoke

`scripts/e2e_smoke.py` is the deterministic pass/fail gate for the integrated
JobForge app. It starts the real FastAPI application on a free localhost port,
uses a temporary SQLite database and output directory, exercises the main
routes, runs a real Typst tailoring pass, updates the application tracker, and
prints one typed JSON verdict.

It does not touch the network, a live ATS, a browser, or an email account.

## Command

```bash
cd $JOBFORGE_REPO
.venv/bin/python scripts/e2e_smoke.py --json
```

- Exit `0` when every check passes.
- Exit `1` when any check fails or the run raises.
- `--json` prints exactly one compact JSON document on stdout.
- Without `--json`, the same verdict is printed as a human-readable checklist
  plus a one-line summary.
- Requires `typst` on `PATH` (the same binary the app uses for resumes).

Pytest gate:

```bash
.venv/bin/python -m pytest tests/test_e2e_smoke.py -q
```

The test calls `run_e2e(timeout_s=30)` and skips when `typst` is unavailable.

## Parameters

| Parameter | Default | Meaning |
|---|---|---|
| `port` / `--port` | `0` | Localhost port. `0` asks the OS for a free port; the actual port is read from the uvicorn socket. |
| `timeout_s` / `--timeout` | `30` | Deadline for server startup and `/healthz` readiness, in seconds. |
| `--json` | off | Emit exactly one compact JSON document. |

`run_e2e(port=0, timeout_s=30) -> dict` is importable and returns:

```json
{
  "ok": true,
  "checks": [{"name": "healthz", "passed": true, "detail": "status=200"}],
  "port": 49953,
  "pdf": "/tmp/jobforge-e2e-.../output/acme/backend-engineer/resume.pdf"
}
```

The temporary directory is removed before `run_e2e` returns. `pdf` records the
path that existed during the run, not a retained artifact.

## What is covered

1. **Configuration and storage.** A `Config` points at a temp data dir, output
   dir, and SQLite database. Sources are empty, the LLM is disabled, email is
   disabled, the browser is headless, and `allow_submit` is false. `db.init_db`
   creates the schema.
2. **Realistic seed data.** A profile has contact fields, one experience entry,
   two facts, skills, education, and a base resume PDF generated in-process with
   pymupdf (no external fixture). One job has a parseable description
   (`Requirements: Python, FastAPI, PostgreSQL`) and a URL.
3. **Real server.** `uvicorn.Server` runs `create_app(config)` on
   `127.0.0.1` in a daemon thread. `port=0` binds an ephemeral port.
4. **Readiness.** `GET /healthz` is polled with `httpx` (proxy environment
   ignored) until it returns 200 or the deadline expires.
5. **Routes.** `GET /`, `/jobs`, `/jobs/{id}`, `/applications`, `/answers`,
   `/profiles`, `/settings`, `/inbox`, `/runs`, `/api/status`, and
   `/api/answers` must all return 200. The job detail page must contain the
   seeded title.
6. **Real tailoring.** `POST /jobs/{id}/tailor` runs the real service layer and
   Typst compiler. The resulting PDF must exist under the temp output dir, be
   one page, have a text layer of at least 200 characters, and contain the
   candidate name. An application row must reference the PDF.
7. **Tracker.** `POST /applications/{id}/status` sets a valid status; the status
   must be persisted in SQLite and the `/applications` tracker page must show the
   seeded company.

## What is NOT covered

- Live ATS discovery or form filling (Greenhouse, Lever, Ashby, Workable,
  SmartRecruiters, Workday).
- Playwright/Chromium. `allow_submit` remains false and no browser launches.
- Captcha detection or human handoff.
- IMAP/email polling or verification-code extraction.
- LLM calls. The LLM is disabled, so tailoring uses the deterministic path.
- Scoring quality beyond the fact that the app renders an unscored job.
- Multi-profile, export/download, and upload flows.

Those require external services or human interaction and must be covered by
separate, explicitly non-deterministic smoke runs.

## Interpreting failures

Each check has a stable name and a detail string. Read the failing check first:

| Check | Meaning |
|---|---|
| `typst-available` | `typst` is missing from `PATH`. Install Typst or run the pytest gate, which skips in this case. |
| `healthz` | The app did not become ready. Inspect the check detail and the `exception` traceback if present. |
| `GET /...` | A route returned a non-200 status. Check the app logs and the route's template/context. This includes `/answers` and `/api/answers` so the mounted editor is covered. |
| `job-detail-title` | The seeded job is missing or the detail template does not render it. |
| `POST /jobs/{id}/tailor` | The tailor route returned an unexpected status or reported a failure in its redirect message. |
| `tailor-application` | The tailor route completed but did not create an application row. |
| `tailor-pdf-*` | The PDF is missing, outside the temp output dir, multi-page, textless, or missing the candidate name. |
| `POST /applications/{id}/status` | The status form was rejected. Check the status value and the route. |
| `application-status-persisted` | The tracker state did not change in SQLite. |
| `tracker-reflects-application` | The `/applications` page does not show the seeded company. |
| `exception` | An unexpected exception escaped. Its detail contains the formatted traceback. |

The process exits non-zero on any failed check, so CI can use the exit code
directly.

## Determinism and review policy

This harness is the pass/fail gate. It uses fixed seed data, a temp database, an
ephemeral localhost port, deterministic tailoring (LLM disabled), and local
assertions only. An agentic or LLM judge may produce advisory commentary, but it
must not override this verdict. Any judge must use a pinned model,
temperature 0, an explicit rubric, and evidence citations.
